# System Monitor — локальный монитор этого Mac

Целевая проверенная машина: Mac15,3, Apple M3, 4P + 4E, 8 GB, macOS 26.5.1.
Исходный контракт: SPEC.md. Монитор работает только с текущим Mac и не имеет облачного контура.

## Контексты

1. Hardware: постоянный macmon Sampler в отдельном потоке; аппаратные показатели.
2. Host: sysinfo и небольшой C bridge к SDK macOS; процессы, память, сеть, накопители, батарея.
3. Docker: локальный Unix socket, Engine API: чтение и адресные операции по подтверждённому плану (см. [ADR управления](ADR-management.md)). Контейнеры не суммируются повторно с Docker VM.
4. History: SQLite, process identity PID + start microseconds, многоуровневые временные buckets.
5. Diagnostics: правила с длительностью, явно измеренный интервал наблюдения.
6. Presentation: React/TypeScript, uPlot, раздельные subscriptions, WebSocket.

## ADR-1. Один Rust agent с библиотекой macmon

- Решение: прямой библиотечный API, фиксированная версия; hardware worker не блокирует HTTP и host collector.
- Альтернатива: дополнительный macmon HTTP daemon. Дополнительный lifecycle не нужен при доступной библиотеке.
- Обоснование: один устанавливаемый бинарник, нет shell spawn на интервале измерений.
- Источники: https://github.com/vladkens/macmon.

## ADR-2. SQLite с ограниченной историей

- Решение: WAL, пакетные записи; buckets содержат count, sum, min, max. Retention применяется транзакционно, дискретные состояния имеют отдельные счётчики.
- Разрешения: 1s до 15m, 5s до 1h, 15s до 6h, 60s до 24h, 300s до 7d, 900s до 30d.
- Альтернатива: хранить все процессы каждую секунду без ограничений. Не соответствует дисковому бюджету.
- Обоснование: индекс времени, ограниченное число строк, точное взвешенное среднее вместо среднего средних.

## ADR-3. WebSocket и отдельный API истории

- Решение: текущая выборка и изменения процессов через WS; история по запросу с ограничением периода и количества точек. После reconnect и foreground происходит синхронизация.
- Альтернатива: частый polling нескольких endpoints. Лишние запросы и обновления React.

## ADR-4. Значение и доступность разделены

- Решение: недоступное численное значение — null, вместе с причиной/статусом. Первое измерение счётчика не создаёт фиктивную нулевую скорость.
- CPU процесса: delta CPU time / monotonic sampling interval, 100% соответствует одному ядру.
- Host CPU и residency macmon — разные измерения, подписываются отдельно.
- Process footprint и RSS имеют отдельные поля; RSS используется только как явно подписанный fallback.
- Network отдельных macOS PID может быть недоступен; общего интерфейсного трафика недостаточно для атрибуции PID.
- Источники: локальный macOS SDK libproc.h, sys/proc_info.h, sys/resource.h.

## Безопасность и эксплуатация

Только 127.0.0.1:9899. Проверка Host и Origin, CORS закрыт, CSP self, GET для чтения; POST управления требует Origin, токен и одноразовый план.
Docker удалённые endpoints не опрашиваются: DOCKER_HOST/context с TCP/SSH дают явное состояние unsupported_remote.
Аргументы процессов могут содержать секреты: отображать локально, не отправлять в сеть; не сохранять полный command line в историю.
История хранится в пользовательском Application Support с приватными правами. LaunchAgent работает от пользователя, KeepAlive восстанавливает процесс.
Release раздаёт статический frontend; Vite только для разработки.

## Проверка готовности

Полный список в SPEC.md. Наличие данных не является завершением. Нужны измерения overhead, проверки CPU/Node/Docker/RAM/disk, закрытого UI, восстановления агента и визуальный polish.
Перезагрузку пользовательского Mac не выполнять автоматически: запуск после login проверяется через launchd bootstrap; фактический reboot отмечается отдельно.

## Интерактивная карта M3

По пользовательскому референсу создана функциональная интерактивная схема, а не точная геометрия die. Числа 4P/4E и 10 GPU проверены локально; 16-core Neural Engine соответствует документации Apple для M3:
https://www.apple.com/newsroom/2023/10/apple-unveils-m3-m3-pro-and-m3-max-the-most-advanced-chips-for-a-personal-computer/

Цвет CPU/GPU зависит от реальных residency/температур. Цвет DRAM — memory pressure macOS. В температурном режиме DRAM и ANE обозначены как недоступные, общая температура CPU не выдаётся за температуру каждого ядра. Cache/fabric не имеют фиктивных показателей. Диаграмма этого Mac предназначена для M3; backend использует аппаратное обнаружение macmon.

Пороговые цвета: CPU activity 75/90%, GPU chart 80/95%, температура 80/90°C. Это уровни визуального внимания, а не утверждение о физических пределах чипа или повреждении. Rule-based диагностика требует длительности; после разрыва наблюдений её непрерывные интервалы сбрасываются.

## Детали нативного collector

Текущая реализация собирает процессы через libproc + sysctl, кэширует command/cwd на 30 секунд, учитывает Mach timebase при вычислении CPU. Sysinfo используется для общего CPU/RAM/network/disk. Ёмкость дисков обновляется раз в 30 секунд; дисковые счётчики — в каждом цикле, без дорогостоящего запроса purgeable storage каждую секунду.


## ADR-5. История читается отдельно от текущих измерений (2026-09-24)

- Решение: каждый HTTP-запрос истории, процесса и событий открывает read-only SQLite connection внутри `spawn_blocking`. Collector сохраняет своё соединение записи. Индекс `samples_time(ts)` ускоряет выборки по времени; база остаётся в WAL.
- Альтернатива: общий mutex для чтения и записи. Длительное чтение накопленной истории задерживало публикацию живых данных; при проверке возраст измерения достигал 38 секунд.
- Обоснование: история — отдельный контекст чтения, live — контекст сбора. Snapshot чтения не требует общей с collector прикладной блокировки. Дополнительное соединение имеет небольшой накладной расход; тяжёлое чтение всё ещё потребляет CPU/I/O, а очистка истории остаётся в потоке collector.
- Проверка: тест держит read transaction, выполняет запись с другого соединения, проверяет старый snapshot до commit и новые данные после него. Read-only connection не разрешает DELETE.
- Источники: [[ddia/03-storage-retrieval]] (OLTP/OLAP и индексы), [[ddia/07-transactions]] (snapshot isolation), [[database-internals/05-transactions-storage]] (WAL). Это ссылки на конспекты автора; механизм SQLite описан в https://sqlite.org/wal.html.

## Анимация охлаждения и подсказки

SVG показывает функциональную, не физически точную конструкцию. Количество вентиляторов и RPM приходят из hardware.fans. Web Animations меняет playbackRate без сброса фазы: 3000 RPM соответствуют одному визуальному обороту за 1.2 секунды (масштаб 1:60). Поток воздуха иллюстративный, не расходомер. Ноль RPM останавливает вращение; при недоступных/устаревших показаниях числовое значение не подменяется нулём.

Анимация приостанавливается вне viewport, в скрытой вкладке, при пользовательской паузе и prefers-reduced-motion. Canvas uPlot использует явный system-ui font stack. Tooltip рисуется в портале body, ограничен границами окна и скрывается при выходе указателя, прокрутке и Escape. Для длительных диапазонов ось включает дату.

Фон охлаждения — статический локальный PNG; крыльчатка и условные линии воздуха — SVG с Web Animations. Источник иллюстрации и ограничения описаны в [COOLING_ASSET.md](COOLING_ASSET.md).

## Полный SSD и AI Gateway

`disk_layout.py` раз в 60 секунд читает `diskutil info/apfs list/list -plist` в отдельном потоке. Основной APFS сопоставляется с физическим store; физическая ёмкость не подменяется ёмкостью тома. Сегменты сверяются с общей ёмкостью; несогласованный расклад заменяется общим occupied-сегментом. Многодисковые схемы помечаются неподдерживаемыми. Метаданные папок и сегменты APFS — разные уровни учёта; размеры clones/snapshots не складываются как гарантированно освобождаемые байты.

Timeweb AI Gateway — опциональный внешний анализ обезличенных снимков по явной кнопке. `workspace-ai.sqlite` хранит ключ и ответы только локально, вне репозитория; права 0600. Endpoint фиксирован, redirects запрещены, ключ не входит в model messages или ответы API. AI не имеет инструментов исполнения. Детали: [WORKSPACES.md](WORKSPACES.md).
