# ADR: рабочие проекты, Git и история роста

## Цель

Найти источники накопления данных и риск потери работы. Мониторинг никогда не является разрешением на удаление. Новый раздел не получает операций удаления веток, worktrees, файлов, Docker-томов или образов.

## Учёт

- Python 3 stdlib helper выполняет пакетный обход и read-only команды Git. Он запускается существующим Rust-агентом отдельно от realtime collector. CLI Python уже входит в требования установки.
- Настраиваемые корни внутри домашней папки. Поиск пропускает .git, зависимости и сборки, не следует symlink. Зарегистрированные Git worktrees внутри выбранной области учитываются отдельно; общий git-dir — один раз. Ветки не считаются копиями файлов.
- Категории размера: рабочие файлы, зависимости, сборки, кэши и общие данные Git. Категория dist/build не гарантирует воспроизводимость: внутри могут быть ценные или отслеживаемые файлы.
- Измерения по метаданным и выделенным блокам; APFS clones, snapshots и sparse files требуют осторожности. Нет обещания освободить сумму отображённых размеров. Ошибка доступа даёт частичный результат, а не ноль.
- Docker читается через существующий локальный API. Физическое место Docker.raw, слои образов, тома и кэш — отдельные показатели, не складываемые безусловно.

## Git и опубликованность

- Сохраняются HEAD, локальные ветки, upstream, ahead/behind по локальным remote-tracking refs, worktree locks, изменения рабочей копии, untracked и stash.
- Локальный upstream не доказывает актуальность удалённой ветки. Отдельная явная сверка читает refs через git ls-remote, не делает fetch/push и не меняет refs пользователя.
- Точное совпадение SHA или доказанная достижимость локального SHA из текущего удалённого tip — только свидетельство о коммите. Несохранённые, untracked, ignored файлы и stash этим не защищены. При отсутствующих объектах или ошибке сети результат «не подтверждено».
- Никаких reset, clean, prune, gc, checkout, worktree remove. Команды имеют таймаут и неинтерактивный режим; статус не обновляет индекс через optional locks.

## История

- Отдельная SQLite development.sqlite, WAL. Снимки с версией схемы, областью поиска, временем начала/конца и доступностью данных. Хранение 90 дней, максимум 1000 снимков.
- Автоматический сбор раз в 6 часов и ручной запуск. В UI сравниваются два реальных снимка; отсутствующая история не заполняется моками. Добавление области поиска не выдаётся за рост накопленных файлов.
- Детерминированные причины внимания: локальные изменения, stash, отсутствие подтверждения remote, блокировка worktree, заметный рост измеренной категории и мало свободного места. Старость ветки сама по себе не означает ненужность.

## AI

- JSON-экспорт содержит агрегаты, условные идентификаторы и факты; без путей, имён проектов/веток, remote URL, файлов, diff, аргументов и секретов. Для ручного AI-разбора сводка передаётся в Timeweb Gateway; локальный экспорт также доступен через API. Имена подставляются в ответ локально.
- Ключ Timeweb хранится только в отдельной локальной SQLite (0600), вне Git. Endpoint фиксирован, redirects запрещены, секрет не возвращается в API, не логируется и не передаётся модели в messages. Платный запрос выполняется только по кнопке; ограничены вход, выход, параллельность и история результатов. Автоповторов нет. Ответ модели структурирован, но остаётся недоверенным текстом без tools или исполнительных действий.
- SystemLanguageModel проверяется на доступность. На этом Mac при проверке: appleIntelligenceNotEnabled. Локальный AI может объяснять агрегаты, но не определяет допуск к удалению и не имеет инструментов исполнения.
