# ADR: локальные данные и адресные операции

## Решение

Новые экраны встроены в основную навигацию. Процессы и память используют существующий WebSocket; управление работает через отдельные POST endpoints агента. Моки не участвуют в основном интерфейсе.

### Ограничения операций

- Агент слушает только 127.0.0.1:9899. POST требует точный Origin и случайный токен текущего запуска, получаемый через same-origin GET. Host и cross-site запросы проверяются для всех путей.
- Операция проходит подготовку: сервер выдаёт одноразовый план на 90 секунд, привязанный к конкретному объекту. Выполнение сериализовано, план потребляется до вызова операции, автоматических повторов нет.
- Процесс: только SIGTERM конкретному PID текущего пользователя; проверяются PID + время запуска непосредственно перед сигналом. Системные пути, Docker, агент и его предки защищены. macOS не предоставляет используемому здесь API атомарную операцию «проверить время запуска и послать сигнал»: остаётся минимальное окно между проверкой и kill. Групповое и принудительное завершение не реализованы.
- Docker: только локальный Unix socket, проверка неизменного сокета и ID движка. Перед выполнением повторно inspect: идентичные ID, имя, состояние, время запуска/остановки, конфигурация и mounts. Удаление только exited/created, DELETE с force=false и v=false. Состояние работающего контейнера дополнительно защищает сам Docker Engine. Остановка только конкретного running контейнера, таймаут Docker 10 секунд. Swarm-контейнеры защищены.
- Тома, образы, BuildKit-кэш — только чтение. Нет prune, удаления папок, изменения Docker.raw, команд через shell, sudo и очистки RAM через purge.
- Размер Docker.raw: allocated blocks отдельно от логического лимита. Стандартный путь может быть недоступен при другой конфигурации. Размеры объектов внутри VM не суммируются как обещанное освобождение SSD.
- Сканер накопителя читает метаданные известных папок, не открывает содержимое, не следует symlink, не пересекает устройства, дедуплицирует hard links. Полный фоновый обход без ограничения общего числа объектов и времени; очереди категорий чередуются, каждые 200 объектов поток делает паузу. Глубина до 128. Автоматический запуск при старте агента и раз в 6 часов, ручной запуск и остановка. Последний результат сохраняется в storage-scan.json. Частичные данные и ошибки доступа видны в UI. APFS clones и snapshots не позволяют гарантировать размер освобождения.
- Журнал операций за текущий запуск доступен в интерфейсе; результаты записываются также в существующий SQLite events.

## Альтернативы

Прямое удаление файлов Docker и массовый prune отвергнуты: они не соответствуют адресному подтверждению и могут затронуть данные проектов. Универсальный shell endpoint не нужен. Для памяти выбран просмотр реального состояния и SIGTERM вместо искусственного резервирования/сброса RAM.

## Проверка

Деструктивные операции не проверяются на существующих пользовательских контейнерах. Контракт Docker тестируется на изолированном Unix HTTP stub. Завершение процесса проверяется только на специально созданном sleep. Накопитель, память, списки Docker и навигация проверяются на реальных read-only данных.
