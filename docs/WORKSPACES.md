# Рабочие проекты

Раздел встроен в основной монитор: **Рабочие проекты** в левом меню.

## Первый запуск

1. Нажмите **Папки** и задайте корни поиска, по одному на строку. По умолчанию используются `~/Documents/ChatGPT` и `~/Desktop/UNIUM DEV`. Учитываются вложенные папки с `.git`, включая связанные worktrees. Папки вне Git остаются в общем разделе **Накопитель**.
2. **Снять сейчас** запускает полный фоновый обход. Можно продолжать работать. Нет ограничения в 60 секунд или 150 тысяч объектов; ошибки доступа дают частичный снимок. Отмена сохраняет предыдущую историю и не создаёт недомеренный «полный» снимок.
3. Снимки повторяются каждые 6 часов после завершения предыдущего обхода. Перезапуск агента не стирает историю. Пока идёт обход, изменение корней заблокировано.
4. После двух снимков доступны график и сравнение. Выберите **Было** и **Стало**, чтобы посмотреть изменение размеров. Области поиска должны совпадать; неполные измерения не выдаются за точный общий прирост.

## Что считается

- Рабочие файлы каждой копии, зависимости (`node_modules`, `.venv`, `Pods`, toolchain), сборки (`build`, `dist`, `.next`, `target`) и кэши. Это классификация по именам папок, а не доказательство, что файлы можно восстановить или удалить.
- Общий git-dir одного репозитория считается один раз, даже при нескольких worktrees. Ветки — ссылки на коммиты, а не дополнительные копии всего проекта.
- Вложенные проекты исключаются из родительской копии. Hard links учитываются один раз в пределах обхода. Symlink и другие файловые системы не обходятся. Метаданные зарегистрированных worktrees вне выбранной области видны, но их содержимое не сканируется.
- Выделенные блоки файлов. APFS clones и snapshots могут разделять блоки: оценка размера не равна обещанию освобождения SSD. Обход не является атомарным: начало и конец измерения указаны на экране.
- Docker.raw измеряется отдельно от данных внутри Docker. Образы, тома, кэш и контейнеры могут разделять слои. Изменения объектов сравниваются только при совпадении ID движка; недоступность Docker не считается нулём. Docker.raw ищется по стандартному пути Desktop; нестандартное расположение может быть недоступно.

## Git: что означает «подтверждено»

Обычный фоновый обход работает локально. Он показывает изменённые, untracked и конфликтующие пути, stash, локальные ветки, upstream, locks и состояние worktrees. Git не обновляет индекс через optional locks. Untracked-папка может учитываться одной записью; ignored файлы входят в размер, но не в статус Git.

**Сверить с remote** запускает новый снимок с `git ls-remote`. Это чтение текущих refs сервера через существующие HTTPS/SSH-настройки. Команда не выполняет fetch, не меняет remote-tracking refs, не пушит и не открывает интерактивный вход. Отсутствующая авторизация, сеть или неподдерживаемый протокол дают «Remote недоступен».

Подтверждение даётся, когда SHA локальной ветки совпадает с текущим upstream на сервере либо локально доказана достижимость коммита из этого upstream. Если tip сервера отсутствует в локальной базе объектов, результат остаётся неизвестным. Ветки без upstream не получают подтверждение автоматически. Проверка не ищет коммит во всех возможных удалённых ветках.

**Подтверждённый коммит не означает, что папку можно удалить.** Несохранённые файлы, untracked, ignored, stash, detached HEAD и данные приложений требуют отдельной проверки. Возраст коммита не означает, что проект давно не использовался. Раздел не удаляет ветки, worktrees, файлы, образы, кэши или тома и не запускает prune / clean / reset / gc.

## История и приватность

Данные находятся в `~/Library/Application Support/System Monitor`:

| Файл | Назначение |
| --- | --- |
| `development.sqlite` | Снимки: 90 дней, максимум 1000; SQLite WAL |
| `workspace-config.json` | Настроенные корни поиска |
| `workspace-status.json` | Прогресс текущего обхода |
| `workspace.lock` | Запрет параллельного запуска сборщиков |

Локальная БД содержит пути проектов, названия веток, SHA, состояния и размеры. Она не хранит содержимое рабочих файлов, diff, Docker env или credentials. Права файлов ограничены текущим пользователем через umask 077.

**Скачать JSON для разбора** создаёт локальный файл из выбранных снимков. Строгий список полей исключает пути, названия проектов/веток, SHA, remote URL и произвольные строки Docker. Остаются время, агрегаты, условные номера проектов и состояния. Экспортный API доступен для отдельного локального скачивания. Основной AI-разбор работает прямо в панели, без ручного переноса JSON.

### Timeweb AI Gateway

В верхней части раздела — краткая AI-сводка, четыре карточки измеренных фактов, до трёх пунктов в секциях «Что происходит», «Что можно сделать» и «Что требует внимания». Обоснование раскрывается отдельно. Графики и технические списки постоянно видны под AI-сводкой. Карточка **Кандидаты на проверку** показывает build + cache; она не утверждает, что эти данные безопасно удалить.

При первом открытии без ключа появляется настройка Gateway. Позже она доступна через **Настройки** в AI-блоке. Введите ключ, нажмите **Проверить и сохранить**, выберите модель из списка Timeweb. По умолчанию выбирается `openai/gpt-4.1-mini`, если она доступна. **Забыть ключ** удаляет его локально, но не отзывает ключ у провайдера.

- Endpoint фиксирован: `https://api.timeweb.ai/v1`; произвольный URL не принимается. HTTP redirects запрещены, TLS проверяется.
- Ключ хранится только в `workspace-ai.sqlite` в каталоге данных приложения (вне проекта и Git), с правами 0600. Это локальная SQLite, не Keychain и не зашифрованное хранилище; доступ защищён правами пользователя. Ключ не возвращается в браузер, не кладётся в localStorage, export, логи или исходники.
- **Разобрать снимки** отправляет в Gateway обезличенную сводку выбранной пары снимков. Имена проектов подставляются в ответ локально. Содержимое файлов, diff, пути, SHA и remote URL не передаются.
- Запросы платные по тарифу Gateway, только по кнопке. Нет автоматического AI-анализа после фонового сканирования и нет автоматических повторов после ошибки/таймаута. До 30 крупнейших рабочих копий на снимок, ограничение размера входа и длины ответа; сокращение явно указано в данных.
- Ответ и расход токенов сохраняются локально, привязаны к паре снимков; до 100 ответов за 90 дней. При новой паре старый ответ не выдаётся за актуальный.
- AI получает только данные и текстовую задачу, без tools и доступа к выполнению команд. Ответ проверяется по структуре и выводится как текст; HTML не исполняется. Окончательное решение о ценности файлов остаётся за пользователем.

Проверка доступности Foundation Models остаётся отдельной необязательной возможностью агента. Timeweb-анализ выполняется удалённой моделью и не использует Neural Engine этого Mac.

## API

- `GET /api/workspaces?before=ID&after=ID` — история, выбранные снимки, прогресс и настройки.
- `GET /api/workspaces/export?before=ID&after=ID` — обезличенный JSON.
- `POST /api/manage/workspaces/scan` с `{}` или `{"verify_remote":true}`.
- `POST /api/manage/workspaces/cancel` — остановить текущий обход.
- `POST /api/manage/workspaces/ai/settings` — ключ и модель, `ai/models` — обновление каталога, `ai/clear` — забыть ключ.
- `POST /api/manage/workspaces/ai/analyze?before=ID&after=ID` — запустить разбор выбранных снимков; результат приходит в `GET /api/workspaces`.
- `POST /api/manage/workspaces/settings` с `{"roots":["/Users/you/projects"]}`.

Все POST требуют штатных проверок localhost, Origin и session token. Корни — существующие папки внутри home, не более 16. Процесс-сканер получает пониженный CPU-приоритет; команды Git имеют таймаут и ограниченный вывод. API не содержит операций очистки проектов.

Тесты используют временные репозитории, worktrees и локальную тестовую БД. Они не модифицируют рабочие проекты пользователя.
